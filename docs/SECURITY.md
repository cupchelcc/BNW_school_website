# นโยบายและแนวปฏิบัติความมั่นคงปลอดภัย (Security Guidelines)
## โครงการ BNW-001 V2: โรงเรียนวัดบางน้ำวน (รอดพิทยาคม)

---

### 1. มาตรการป้องกันช่องโหว่ทางเทคนิค (Vulnerability Mitigation)

#### 1.1 การป้องกัน SQL Injection
- **แนวทาง:** ระบบใช้ **Drizzle ORM** ร่วมกับ **LibSQL/SQLite** ซึ่งประมวลผลคำสั่ง SQL ในรูปแบบ Parameterized Queries ทั้งหมด 100%
- **ผลลัพธ์:** ข้อมูลอินพุตจากผู้ใช้จะไม่ถูกนำไปต่อสตริง (String Concatenation) ในคำสั่ง SQL โดยตรง ทำให้ป้องกันการโจมตี SQL Injection ได้อย่างเด็ดขาด

#### 1.2 การป้องกัน Cross-Site Scripting (XSS)
- **แนวทาง:** ระบบใช้ **React 19 / Next.js 15** ซึ่งมีระบบ Auto-escaping ข้อมูลข้อความทุกตัวก่อนแสดงผลลง DOM
- ในส่วนของ **Visual Page Builder:** ข้อมูลของบล็อกทั้ง 15 ประเภทถูกกำหนดโครงสร้างเป็น JSON Schema ที่เข้มงวด และถูก Render ผ่าน Components ที่กำหนดไว้ล่วงหน้าเท่านั้น ไม่อนุญาตให้ผู้ใช้แทรกสคริปต์ `<script>` หรือ HTML ดิบที่ไม่ปลอดภัย

#### 1.3 การป้องกัน Cross-Site Request Forgery (CSRF) & Session Hijacking
- **แนวทาง:** จัดเก็บเซสชันในรูปแบบ **HTTP-Only, Secure, SameSite=Lax Cookie** ทำให้สคริปต์ภายนอกไม่สามารถเข้าถึง Cookie ได้ผ่านทาง JavaScript (Document.cookie)
- ตรวจสอบความถูกต้องและวันหมดอายุของเซสชันที่ฝั่งเซิร์ฟเวอร์ทุกครั้งเมื่อมีการเรียกใช้ API

#### 1.4 การรักษาความปลอดภัยรหัสผ่าน (Password Security)
- **แนวทาง:** รหัสผ่านทุกบัญชีจะถูกแฮชด้วยอัลกอริทึม **Bcrypt** (Salt rounds = 10) ก่อนบันทึกลงฐานข้อมูล
- **ข้อห้ามเด็ดขาด:** ห้ามบันทึกรหัสผ่านเป็นข้อความธรรมดา (Plain Text) และห้ามใส่รหัสผ่าน Production ใน Source Code

#### 1.5 การควบคุมความปลอดภัยในการอัปโหลดไฟล์ (File Upload Security)
- ตรวจสอบ MIME Type โดยอนุญาตเฉพาะรูปภาพ (`image/jpeg`, `image/png`, `image/webp`, `image/svg+xml`) และเอกสารการศึกษา (`application/pdf`, `.docx`, `.xlsx`)
- จำกัดขนาดไฟล์ไม่เกิน **10 MB** ต่อไฟล์
- ตั้งชื่อไฟล์ใหม่ด้วยการสุ่มตัวเลขเวลาและรหัสแบบปลอดภัย (Randomized Unique Filename) เพื่อป้องกัน Path Traversal

### 2. การควบคุมสิทธิ์ตามบทบาท (Role-Based Access Control - RBAC)

ระบบกำหนดให้มีการตรวจสอบสิทธิ์ที่ **Server-Side API Routes** เสมอ ไม่พึ่งพาเพียงการซ่อนปุ่มบน UI:

| ความสามารถ | Super Admin | Site Admin | Editor | Author |
|---|:---:|:---:|:---:|:---:|
| จัดการและเปลี่ยนสิทธิ์ผู้ใช้ | ✅ | ❌ | ❌ | ❌ |
| ปรับแต่งค่า Theme และ Logo | ✅ | ✅ | ❌ | ❌ |
| สร้างและแก้ไขเนื้อหาของตนเอง | ✅ | ✅ | ✅ | ✅ |
| เผยแพร่เนื้อหา (Publish) สู่สาธารณะ | ✅ | ✅ | ✅ | ❌ |
| ลบไฟล์ในคลังสื่อและเนื้อหาผู้อื่น | ✅ | ✅ | ❌ | ❌ |
| สำรองและกู้คืนฐานข้อมูล | ✅ | ❌ | ❌ | ❌ |

---

### 3. การบันทึกและตรวจสอบกิจกรรมระบบ (Audit Logging)
ทุกการกระทำสำคัญ เช่น:
- การเข้าสู่ระบบสำเร็จและล้มเหลว (`LOGIN_SUCCESS`, `LOGIN_FAILED`)
- การสร้าง เผยแพร่ หรือลบหน้าเว็บและข่าว (`CREATE_PAGE`, `PUBLISH_NEWS`, `DELETE_NEWS`)
- การอัปโหลดหรือลบสื่อ (`UPLOAD_MEDIA`, `DELETE_MEDIA`)
- การแก้ไขธีมหรือการตั้งค่าระบบ (`UPDATE_THEME`)
จะถูกบันทึกลงตาราง `audit_logs` พร้อมวันเวลา รหัสผู้ใช้ อีเมล และ IP Address เสมอ

---

### 4. การจัดการความลับและค่าคอนฟิก (Secrets Management)
- ข้อมูลความลับ เช่น `AUTH_SECRET`, รหัสผ่านฐานข้อมูล และคีย์ Cloudflare จัดเก็บในไฟล์ `.env` ซึ่งถูกระบุไว้ใน `.gitignore`
- ใน Source Code มีเพียงไฟล์ `.env.example` ที่แสดงเฉพาะโครงสร้างตัวแปรและค่าตัวอย่างที่ไม่ใช่ความลับ
